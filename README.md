# Growing a Neural Network in Breadth, Depth, and Time

Code for **"Growing a Neural Network in Breadth, Depth, and Time"** (Butkus, Garzón Gupta & Kriegeskorte, NeurIPS 2026).

[Paper (OpenReview)](https://openreview.net/forum?id=xl72oIaJ4k) · [Checkpoints and results (Zenodo)](https://doi.org/10.5281/zenodo.24472458)

## Overview

This repository contains the code for a multi-resource cost framework that jointly optimizes three axes of neural network capacity in a single recurrent CNN:

- **Breadth**: the number of active channels per layer
- **Depth**: the number of active layers
- **Time**: the number of recurrent timesteps used for inference

The model is a recurrent convolutional network with lateral and top-down connections. At each timestep, the network reads out logits from all layers and learns to mix them across timesteps via a differentiable *time-selection* mechanism. A joint cost is imposed on all three resources through differentiable penalty terms that are annealed during training:

- `SpaceCost`: L1-norm of sorted weight magnitudes, weighted by layer/channel rank. Promotes sparse use of depth and breadth.
- `TimeCost`: expected timestep used, weighted by timestep rank. Promotes early stopping.
- `ErrorCost`: standard cross-entropy classification loss.

The framework is configured via [Hydra](https://hydra.cc) and supports MNIST, CIFAR-10, CIFAR-100, and Tiny ImageNet.

## Installation

The project uses [Poetry](https://python-poetry.org/) and requires **Python 3.12 or 3.13** (PyTorch 2.7 has no wheels for newer versions).

```bash
# Clone the repository
git clone https://github.com/eivinasbutkus/growing-a-neural-network-in-breadth-depth-and-time.git
cd growing-a-neural-network-in-breadth-depth-and-time

# Install dependencies with Poetry (point it at Python 3.12 or 3.13 if that is not your default)
poetry env use python3.12
poetry install

# Or install in an existing environment
pip install -e .
```

Key dependencies (see `pyproject.toml` for pinned versions):

| Package | Purpose |
|---|---|
| `torch ≥ 2.5` | Model training |
| `torchvision` | Image transforms |
| `hydra-core` | Config management |
| `datasets` | HuggingFace dataset loading |
| `tensorboard` | Training metrics |
| `matplotlib`, `seaborn`, `plotly`, `kaleido` | Figures (`kaleido` exports plotly figures to PDF) |
| `scikit-learn`, `statsmodels` | Analysis in notebooks |

Datasets are downloaded automatically from HuggingFace Hub on first use and cached under `data/datasets/`.

Exporting plotly figures from the notebooks requires a Chrome/Chromium browser, which `kaleido` uses for rendering. If none is installed, or figure export fails with a browser error, install a compatible copy with:

```bash
poetry run plotly_get_chrome -y
```

## Pretrained Checkpoints and Results

Precomputed evaluation results and trained checkpoints for all experiments in the paper are available at:

**Zenodo: [doi.org/10.5281/zenodo.24472458](https://doi.org/10.5281/zenodo.24472458)**

| Archive | Size | Contents |
|---|---|---|
| `results.tar` | 2.75 GB | Evaluation results (`results.npz`), occlusion results, attribution results, and pruning results/masks for every model. **Sufficient to regenerate all figures.** |
| `checkpoints.tar` | 7.38 GB | Final-epoch checkpoint (`checkpoint_149.pt`) and training config for every model. Only needed to re-run evaluation or to use the trained models. |

Both archives cover the three experiments `breadth_depth_time_v7`, `time_selection`, and `datasets_v4`. Download and extract them in the repository root:

```bash
# results (enough to regenerate all figures)
wget https://zenodo.org/records/24472458/files/results.tar && tar -xf results.tar && rm results.tar

# checkpoints (optional)
wget https://zenodo.org/records/24472458/files/checkpoints.tar && tar -xf checkpoints.tar && rm checkpoints.tar
```

This produces `results/experiment_<name>/model-<overrides>/instance<N>/` and `checkpoints/experiment_<name>/<dataset>-<overrides>/instance<N>/`.

With `results/` in place, the notebooks run without any checkpoints: evaluation is skipped for every model whose result files already exist.

## Training a Single Model

All scripts use [Hydra](https://hydra.cc) for config management. Override any config key on the command line with `key=value`.

**Basic training run (CIFAR-10, default config):**

```bash
python scripts/train.py
```

Checkpoints are saved to `checkpoints/experiment_default/cifar10/instance0/`.

**Train a model from one of the paper's experiments with specific cost weights:**

Pass the experiment config with `--config-name` (this is how the cluster jobs are run). Its swept keys (`experiment.variables`) are included in the checkpoint directory name, so runs with different weights do not overwrite each other. Set `experiment.name` to keep your runs separate from the downloaded checkpoints.

```bash
python scripts/train.py --config-name=config_breadth_depth_time_v7 \
  experiment.name=my_run \
  costs.space.lam_breadth=10.0 \
  costs.space.lam_depth=10.0 \
  costs.time.lam=0.2
```

Checkpoints are saved to `checkpoints/experiment_my_run/cifar10-costs.space.lam_breadth=10.0-costs.space.lam_depth=10.0-costs.time.lam=0.2/instance0/`.

**Common overrides:**

| Key | Default | Description |
|---|---|---|
| `dataset` | `cifar10` | Dataset name (`mnist`, `cifar10`, `tiny-imagenet`) |
| `costs.space.lam_breadth` | `1.0` | Breadth penalty weight |
| `costs.space.lam_depth` | `1.0` | Depth penalty weight |
| `costs.time.lam` | `1.0` | Time penalty weight |
| `model.time_selection.scheme` | `adaptive` | Time selection: `adaptive` or `fixed` |
| `train.instance` | `0` | Instance index (for multiple seeds) |
| `train.n_epochs` | `150` | Number of training epochs |
| `train.compile_model` | `True` | Use `torch.compile` (disable on older GPUs or if compilation fails) |

**Evaluate a trained model** (same arguments as for training):

```bash
python scripts/evaluate.py --config-name=config_breadth_depth_time_v7 \
  experiment.name=my_run \
  costs.space.lam_breadth=10.0 \
  costs.space.lam_depth=10.0 \
  costs.time.lam=0.2
```

Results are saved to `results/experiment_my_run/model-costs.space.lam_breadth=10.0-costs.space.lam_depth=10.0-costs.time.lam=0.2/instance0/results.npz`.

## Reproducing Table 1 Experiments

Each experiment is defined by a Hydra config in `config/`. The helper script `scripts/cluster/create_cluster_jobs_files.py` generates both a job-list `.txt` file (one training/evaluation command per line) and a corresponding SLURM array script for your cluster. Adjust the conda environment and resource lines in the generated script to match your cluster.

**Step 1: generate job files and SLURM script for an experiment:**

```bash
python scripts/cluster/create_cluster_jobs_files.py \
  --config-name=<config_name>  # see table below
```

**Step 2: submit the generated scripts to your SLURM cluster:**

```bash
sbatch scripts/cluster/<experiment>/cluster_sbatch_<experiment>_train.sh
sbatch scripts/cluster/<experiment>/cluster_sbatch_<experiment>_evaluate.sh
```

The three experiments corresponding to Table 1 are:

| Experiment | Config | Sweep |
|---|---|---|
| Breadth × depth × time grid | `config_breadth_depth_time_v7` | `lam_breadth` × `lam_depth` × `lam_time`, 3 instances (648 runs) |
| Time-selection scheme comparison | `config_time_selection` | `{fixed, adaptive}` × `lam_time ∈ {0, 0.1, …, 1.0}`, 10 instances (220 runs) |
| Dataset complexity comparison | `config_datasets_v4_train` | `{mnist, cifar10, tiny-imagenet}` × `lam_breadth` × `lam_depth` × `lam_time`, 5 instances |

The breadth × depth analysis (`config_breadth_depth`) uses the `lam_time = 0` slice of the breadth × depth × time grid, so it needs no separate training runs.

## Analysis and Figure Generation

After evaluation results have been computed (or downloaded), open the notebooks in `notebooks/final_notebooks/` in order:

| Notebook | Content |
|---|---|
| `01_breadth_depth.ipynb` | Breadth vs. depth Pareto frontier; weight-norm heatmaps; attribution (GradCAM, image perturbation) |
| `02_time.ipynb` | Time-selection distributions; occlusion robustness; fixed vs. adaptive scheme comparison; comparison with human data (CIFAR-10H) |
| `03_breadth_depth_time.ipynb` | Joint breadth × depth × time Pareto surface |
| `04_datasets_experiment.ipynb` | Resource allocation as a function of dataset complexity across MNIST / CIFAR-10 / Tiny ImageNet |

Each notebook loads precomputed `.npz` result files from `results/` and writes figures to `figures/`.

To run all notebooks non-interactively:

```bash
jupyter nbconvert --to notebook --execute notebooks/final_notebooks/01_breadth_depth.ipynb
jupyter nbconvert --to notebook --execute notebooks/final_notebooks/02_time.ipynb
jupyter nbconvert --to notebook --execute notebooks/final_notebooks/03_breadth_depth_time.ipynb
jupyter nbconvert --to notebook --execute notebooks/final_notebooks/04_datasets_experiment.ipynb
```
